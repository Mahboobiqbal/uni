# University Site Redesign

Use this skill when redesigning a complete university website with 10–40 pages.

## Objective

Transform an existing university website into a cohesive, premium, editorial, institution-grade digital experience.

The result must feel intentional, credible, distinctive, and crafted—not like a generic AI-generated SaaS landing page.

## Phase 1 — Understand the university

Before designing anything, read the entire existing website.

Analyze:

- Homepage
- About
- Academics
- Faculties, schools, departments, and programs
- Admissions
- Research
- Faculty and staff
- Campus life
- News
- Events
- Alumni
- Libraries
- Student services
- Policies
- Contact
- Footer links
- Sitemap
- Navigation menus
- Existing content types

Create `UNIVERSITY-BRIEF.md` containing:

1. University purpose and positioning
2. Core message and brand personality
3. Primary audiences and their goals
4. User journeys for prospective students, parents, current students, faculty, researchers, alumni, employers, and community members
5. Academic hierarchy: university, faculties, schools, departments, degrees, programs
6. Full content inventory
7. Page-by-page audit: keep, merge, move, rewrite, or remove
8. Missing content and structural gaps
9. Content model: program, faculty member, news article, event, research project, department, campus facility, admission step
10. Brand constraints: colors, logo, language, accessibility, cultural context
11. Reference universities to study for structure and quality, never to copy

## Phase 2 — Rebuild the information architecture

Create `SITEMAP.md`, `URL-MAP.md`, and `NAVIGATION.md`.

Design a complete 15–30 page structure.

Required hubs:

- Home
- About
- Academics
- Admissions
- Research
- Campus Life
- Faculty & Staff
- News & Events
- Alumni
- Contact

Define:

- Primary navigation
- Secondary navigation
- Utility navigation
- Footer navigation
- Breadcrumbs
- URL hierarchy
- Internal linking
- Search taxonomy
- Mobile navigation
- Orphan-page prevention
- Redirect plan for changed URLs

Every repeated content type must use one consistent template:

- Program
- Department
- Faculty member
- News article
- Event
- Research project
- Campus facility
- Admission step
- Contact location

## Phase 3 — Create the layout system

Create `LAYOUT-SYSTEM.md`.

Do not generate pages randomly. First define reusable page blueprints.

Required templates:

1. Homepage
2. About university
3. Academics hub
4. Faculty/school hub
5. Program listing
6. Individual program
7. Department page
8. Faculty profile
9. Admissions hub
10. Admission process
11. Research hub
12. Research project
13. Campus life hub
14. Student service page
15. News hub
16. News article
17. Events hub
18. Event detail
19. Alumni page
20. Contact page
21. Search results
22. 404 page

For every template define:

- Page objective
- Primary audience
- Content blocks in exact order
- Visual hierarchy
- Image treatment
- Calls to action
- Internal links
- Mobile behavior
- Accessibility requirements
- Empty-state treatment
- Content-loading behavior

## Phase 4 — Create the card system

Create `CARD-SYSTEM.md`.

Cards must have a purpose. Never use cards as decoration.

Define these reusable card types:

1. Program card
2. Faculty card
3. Department card
4. News card
5. Event card
6. Research card
7. Campus-life card
8. Stat card
9. Quick-link card
10. Testimonial card
11. Announcement card
12. Deadline card
13. Location card
14. Gallery card

For every card define:

- Purpose
- When to use it
- When not to use it
- Required fields
- Optional fields
- Image ratio
- Typography hierarchy
- Grid placement
- Hover behavior
- Mobile layout
- Accessibility requirements
- Example content

Do not repeat the same card grid on every page. Use varied editorial layouts: feature story, directory, timeline, index, profile, calendar, map, and narrative sections.

## Phase 5 — Apply premium visual direction

Use Taste and Hallmark principles.

The design must be:

- Editorial, institutional, confident, warm, and modern
- Rooted in Sowat University’s real identity and community
- Typography-led, with strong hierarchy and generous whitespace
- Restrained in color, imagery, and motion
- Accessible on mobile and desktop
- Coherent across every page

Avoid:

- Generic centered hero sections
- Purple gradients and gradient text
- Emoji as icons
- Stock-photo clichés
- Identical three-column card grids everywhere
- Decorative animation
- Fake testimonials or invented facts
- Template-like SaaS layouts

Use real university photography, faculty portraits, student stories, campus imagery, and local context wherever available.

## Phase 6 — Produce the redesign package

Before implementation, output these documents:

1. `UNIVERSITY-BRIEF.md`
2. `SITEMAP.md`
3. `URL-MAP.md`
4. `NAVIGATION.md`
5. `CONTENT-MODEL.md`
6. `LAYOUT-SYSTEM.md`
7. `CARD-SYSTEM.md`
8. `PAGE-BLUEPRINTS.md`
9. `DESIGN-TOKENS.md`
10. `TYPOGRAPHY.md`
11. `COLOR-SYSTEM.md`
12. `MOTION-SYSTEM.md`
13. `ACCESSIBILITY.md`
14. `IMPLEMENTATION-PLAN.md`

Only begin implementation after the user approves the architecture and design system.

## Quality bar

The final result should feel like a world-class university website:

- Clear purpose on every page
- Strong hierarchy and effortless navigation
- Distinctive typography and imagery
- Purposeful motion
- Consistent components
- Excellent mobile experience
- Fast, accessible, and maintainable code
- A design system that can scale to new programs, faculty, news, and events
